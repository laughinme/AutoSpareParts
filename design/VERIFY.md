# Проверка редизайна

## 5 ноября 2026

- Vite, TypeScript и ESLint прошли в отдельной локальной копии. Системные файлы с флагом `dataless` сверены с индексом Git и взяты из того же коммита. Зависимости восстановлены по версиям из локального npm-инвентаря. Lockfile в рабочей папке не менялся.
- Playwright проверил каталог на 1440×900, 1366×768, 390×844 и 320×800. Горизонтального переполнения нет. Записана прокрутка вперёд и назад на 1440 и 390 px.
- Проверены быстрый фильтр состояния, поиск с клавиатуры, очистка запроса, пустая выдача и ошибка загрузки, мобильные фильтры с возвратом фокуса, переход из каталога в карточку с прокруткой к началу, добавление и изменение количества, открытие формы оформления, отправка формы входа, переключение на регистрацию, гараж, личный кабинет и рабочие экраны ролей. Заказы, кабинет продавца и админ-панель дополнительно проверены на ширине 390 px.
- Браузер использовал тестовые ответы API. Проверка оплаты завершилась на форме адреса. Реальный Stripe не вызывался.
- Линтер DESIGN.md сообщил 0 ошибок. Vite сохранил предупреждение о размере основного JS-бандла.

## Предыдущая версия

Проверка проводилась в Chromium через Playwright. Скриншоты находятся в `design/captures/`.

## Сборка и типы

- `npm ci` по исходному package-lock.json во временной копии `/tmp/autospare-redesign-check`.
- `npm run build`: успешно. Сохраняется предупреждение Vite о размере основного JS chunk (около 707 kB до gzip).
- `tsc -b --pretty false`: успешно.
- `npx -y @google/design.md lint DESIGN.md`: 0 ошибок, 3 допустимых предупреждения о токенах, используемых в CSS.
- Текущий ESLint проекта настроен только на JavaScript/JSX и не проверяет TypeScript/TSX; основная проверка кода — TypeScript и браузерные сценарии.

Временная копия потребовалась из-за файлового флага `dataless` и зависания чтения части исходного node_modules. Версии зависимостей и lockfile в репозитории не менялись.

## Браузерные сценарии

- Каталог: 1440×900, 1366×900, 390×844; без горизонтального переполнения страницы.
- Вход, переключение на регистрацию и возврат к форме входа.
- Поиск, отсутствие результатов, сброс фильтров.
- Состояние товара, диапазон цены, выбор марки и передача make_id.
- Добавление в корзину и изменение количества.
- Мобильные фильтры и навигация в корзину.
- Товар, профиль, кабинет продавца и админ-панель на компьютере и телефоне.
- Ошибка каталога, повторная загрузка и восстановление результатов.
- Переход к поиску с клавиатуры, видимый фокус, prefers-reduced-motion.

API перехватывался только в тестовом браузере. Тестовые товары и пользователи не добавлялись в продукт. Для проверки изображений использованы локальные фотографии из seed assets. Реальные аккаунты, заказы, платежи и данные сервера не изменялись. Проверка оплаты и реального Stripe onboarding не выполнялась.
